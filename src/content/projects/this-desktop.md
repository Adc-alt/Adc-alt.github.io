## The project

The site you are reading. It started as a 23-line `index.html` written to
understand how the web works underneath, went through a version with an arcade
cabinet look, and is now a Windows XP desktop: a BIOS-style boot screen, the
wallpaper, the taskbar and the portfolio inside windows.

## Decisions

**None of this is generated by JavaScript.** The windows come out of the build as
ordinary HTML and the script only opens, drags and closes them. If the browser
painted the content, a search engine would see an empty desktop, and redoing it
afterwards would have meant rewriting the windows entirely.

**The navigation is the URL, not a click handler.** The Menu entries are plain
anchors to `#section-…`. Nothing intercepts the click: the browser sets the hash
and a `hashchange` listener swaps the pane. The back button and links you can
paste into an email both fall out of that, and there is no history code to get
wrong.

**Stacked is the base and the desktop is the enhancement.** You do not drive a
desktop with a finger — and you cannot fit a 700px reading pane between a menu
and a contact card on a narrow screen either — so below 1204px the windows stop
being absolute and stack in a column. The desktop rules live inside a media query and hang off a class
that an inline script in the `<head>` sets: intended consequence, without
JavaScript the site falls back to stacked mode, which is readable. Written the
other way round it would take two copies of the same rules.

**The taskbar colours are measured, not estimated.** They come from sampling XP
screenshots pixel by pixel, and the whole derivation lives in a module with a
test. One thing is approximate — the window colours, because I could not find a
native capture to sample — and it is marked as such in the component itself. The
difference between what is measured and what is eyeballed is the kind of thing
you forget in six months if you do not write it down.

**Astro and zero interface dependencies.** The content does not change between
visitors, so there is no reason to ship a framework to the browser. Tailwind went
too when the arcade version was retired: the desktop is component-scoped CSS and
did not need it.

## What is inside it

- A boot screen traced off a reference with the inspector: timings, colours and
  line breaks measured, not invented.
- A window manager of its own: dragging with Pointer Events, a clamp so a window
  cannot be pushed off the screen, a cascade on open and `z-index` by order of
  use.
- Typed content collections with Zod: a `.md` with one field wrong breaks the
  build instead of publishing a broken window.
- Every bit of motion behind `prefers-reduced-motion`. No exceptions.
- Deploy through GitHub Actions. Push to `main` → build → Pages, about 40
  seconds.
